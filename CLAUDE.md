# Languages & Success (L&S) — contexte projet

Site marketing + **espace documents** pour un organisme de formation en langues (Nice, certifié Qualiopi). FR. Itérations rapides, style éditorial chaud (rose-gold).

## Stack
- Front : **HTML/CSS/JS statique, sans framework**. CSS partagé `assets/site.css`. Nav/footer injectés par `assets/partials.js`.
- Back : **Node + Express** (`server.js`) qui sert le site **et** une API REST. Base = fichier **`data/db.json`** + fichiers dans **`data/uploads/`**. Auth bcrypt + JWT (token en `localStorage` côté client).
- **Robustesse DB** (`loadDB`/`save`/`backupDB`) : mots de passe **hachés bcrypt** (jamais en clair) ; **écriture atomique** (`.tmp` + `fs.renameSync`, pas de fichier à moitié écrit si crash) ; **sauvegardes horodatées rotatives** dans `data/backups/` (snapshot au démarrage + toutes les 6 h, 60 max ≈ 2 semaines) ; **auto-restauration** depuis le backup valide le plus récent si `db.json` est corrompu/illisible (sinon base neuve). `save()` appelé à chaque mutation = sauvegarde permanente. (Migration SQLite = piste future si besoin de concurrence/chiffrement au repos.)
- Anim héros : `morph.js` (canvas 2D, nuage de particules + logo). `medallion.js`/`sphere.js`/`worldmap.js`/`painting.js` = en réserve, non chargés.
- **i18n (langue du site)** : sélecteur dans le header (pastille `FR ▾` desktop, grille dans le drawer mobile), langues FR (source) / EN / ES / IT / RU / ZH. Moteur `assets/i18n.js` (injecté par `partials.js` comme account.js) : dictionnaires « texte FR normalisé → traduction » appliqués aux nœuds texte + attributs (placeholder/title/aria-label/alt), MutationObserver pour le DOM injecté, persistance `localStorage 'ls-lang'`, `<html lang>` mis à jour, retour FR = restauration des originaux. **TOUT le site vitrine est traduit** : dictionnaires par langue dans `assets/i18n-{en,es,it,ru,zh}.js` (~300 clés chacun, chargés À LA DEMANDE par le moteur — un visiteur FR ne charge rien), couvrant chrome + index + formations (+ modal certifications de certs.js) + financement + entreprises + à-propos + contact + test (UI/niveaux) + blog + page espace-documents. L'**app espace-documents est traduite aussi** (~140 clés : auth, dashboard, dossiers/chat/canaux, notifications, picker + modales de génération, statuts QS/présence, dialogues) — les libellés composites (« Dossier — {nom} », « Séance N », « Bonjour {prénom} », textes de notifs stockés en base, titres numérotés du picker) restent FR par construction. Restent en FR : pages légales (CGV/mentions/confidentialité/RI, volontaire — la version française fait foi), les **documents générés** (serveur, toujours français), les explications de correction du test. ⚠️ selects du test : `value="Anglais"` etc. explicites (le texte affiché se traduit, la value FR pilote la banque de questions) ; formations.html capture le nom FR des langues avant traduction pour le lien `?lang=`. ⚠️ Les zones sous `data-i18n-skip` ne sont JAMAIS traduites — posé sur `#q-text`, `#opts`, `#res-correction` du test de niveau pour que les questions restent dans la langue TESTÉE quel que soit le changement de langue du site (même en plein test).

## Lancer / arrêter
- **Port** : `process.env.PORT || process.argv[2] || 3000`. **Défaut = 3000** (aligné avec la prod) ; en **local on lance toujours sur 8000** : `node server.js 8000` → http://localhost:8000. (Sert site + API.) La preview MCP utilise 8011.
- Le port peut être passé en argument : `node server.js 8011`.
- Données sensibles bloquées par le serveur (`/data`, `node_modules`, `server.js`).
- ⚠️ Toujours **un seul** serveur Node sur un port donné (sinon il écrase `db.json`). Tuer le port avant de relancer.

### API principales
`POST /api/signup|login`, `GET /api/me`, `GET /api/users`,
`GET|POST /api/groups`,
`GET|POST /api/messages?group=&channel=` (commun|prive),
`GET|POST /api/documents?group=&channel=` (+ `/:id/download?token=`),
`GET /api/notifications` + `POST /api/notifications/read|delete{id}|clear`, `GET /api/admin/overview`.
Données : `db.json` = `{users, groups, docs, messages, notifs, secret}`.
- **Notifications** : cloche **pollée toutes les 20 s** (`startNotifPoll`, le formateur voit en live quand l'apprenant répond, sans recharger). Modale = suppression **individuelle** (croix par ligne, `POST /api/notifications/delete`) + **« Tout supprimer »** (`POST /api/notifications/clear`).
- **E-mails de notification (SMTP OVH)** : module dans server.js (`mailConfig`/`sendMailSafe`/`mailHtml`, dépendance `nodemailer`). Config **HORS Git** (⚠️ jamais de mot de passe dans le code) : `data/smtp.json` `{host,port,secure,user,pass,from,siteUrl}` — prod/local : `ssl0.ovh.net:465`, auth + **expéditeur `"Languages & Success" <admin@languagesandsuccess.com>`** — ou variables d'env `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM`, `SITE_URL`. Sans config ou sans module → e-mails **désactivés proprement** (log `✉ … désactivés`, tout le reste fonctionne). Branché sur le **flux de signature des feuilles de présence** (les **3 types** elearning/presentiel/test passent par les 2 mêmes routes) : `POST /api/presence/send` → mail à l'**apprenant** « Un document à signer vous attend » (bouton → espace documents) ; `POST /api/presence/:id/sign` → mail au **formateur** (l'envoyeur `p.by`) « Document signé par X ». **Jamais d'envoi vers `@ls.fr`** (comptes démo, garde-fou dans `sendMailSafe`). Envoi **fire-and-forget** (ne bloque jamais la réponse API, erreurs loguées `✉`). Gabarit `mailHtml` = **carte type modal** : fond crème `#f8f2e7`, case `#fffaf0` bordure `#e6dccb` arrondie, **logo en pièce inline** (`cid:lslogo`, attaché automatiquement par `sendMailSafe` depuis `assets/ls-logo.png`), wordmark « Languages & Success » avec **seul le & en accent italique**, bouton accent, pied réduit à « Vous recevez cet e-mail… » + fallback texte. **En PROD** : pas de fichier sur le serveur — le workflow `deploy.yml` écrit `.env` depuis le **secret GitHub `ENV_FILE`** (repo → Settings → Secrets → Actions), auquel il faut ajouter `SMTP_HOST=ssl0.ovh.net` / `SMTP_PORT=465` / `SMTP_USER=admin@languagesandsuccess.com` / `SMTP_PASS=…` ; `docker-compose.yml` passe ces variables au conteneur (défaut expéditeur = `"Languages & Success" <SMTP_USER>`, `SITE_URL` par défaut). Variables vides → mails désactivés proprement.
- **Sauvegarde OFFSITE quotidienne** (module dans server.js : `backupCfg`/`buildDataArchive` (mini-tar POSIX + gzip, zéro dépendance)/`runOffsiteBackup`/`offsiteTick`) : archive `ls-data-<date>.tar.gz` de `data/` (db.json + uploads + smtp.json ; **exclus** : backups/ locaux, db.json.tmp, backup.json) envoyée ~1×/jour sur **Backblaze B2** (API native via fetch), rétention 30 archives. Config **HORS Git** : env `B2_KEY_ID`/`B2_APP_KEY` (+ `B2_BUCKET_ID` si clé non limitée au bucket — sinon bucketId auto via `allowed`) ou `data/backup.json` `{keyId,appKey}` / `{local:"chemin"}` (mode disque local, utilisé pour les tests). Sans config → **désactivée proprement** (log `🗄 …`). **Cadence : 4×/jour à 8/12/16/20 h heure de Paris** (`BACKUP_SLOTS` + `parisHour` via `Intl` — le conteneur est en UTC ; tick toutes les 15 min, garde 3,5 h entre 2 envois, robuste aux redéploiements). **Rétention** : toutes les archives des 3 derniers jours + la dernière de chaque jour sur 30 jours (les 5 plus récentes sont toujours gardées). Statut persisté `db.backupStatus` (dont `users`/`docs`). Routes admin : `GET /api/admin/backup-status`, `POST /api/admin/backup-run` (`{force:true}` pour passer outre le garde-fou). Tout est en try/catch : un échec ne touche jamais le site.
  - **Durcissements issus de l'audit adversarial (25/07/2026)** — ⚠️ ne pas régresser : (1) `addFile` **borne la lecture à la taille annoncée** (`createReadStream {start,end}`) et complète par des zéros si le fichier a rétréci — sans ça, un fichier qui grossit pendant l'archivage (téléversement multer, qui écrit directement à l'emplacement final) désynchronise le flux tar et **fait disparaître en silence tous les fichiers suivants** ; (2) `done.catch()` + drapeau `streamErr` : une erreur d'écriture ne peut plus produire un rejet orphelin qui **tuerait le process** ; (3) noms > 100 octets : champ `prefix` ustar, sinon **erreur explicite** (jamais de troncature silencieuse) ; (4) **garde-fou anti-base-vide** : refus si le nombre de comptes s'effondre (< 50 % de la dernière sauvegarde réussie) — sinon un volume non monté ferait tourner la rétention sur des archives vides ; (5) rétention **filtrée sur le motif exact** des archives + pagination `nextFileName` + jamais moins de 5 archives ; (6) **refus des buckets publics** (`bucketType !== allPrivate`) : l'archive contient données personnelles, hachages, `db.secret` et le mot de passe SMTP ; (7) SHA1 en flux + refus au-delà de 350 Mo (pas d'OOM) ; (8) `AbortSignal.timeout` sur tous les appels B2 ; (9) **alerte e-mail à l'admin** en cas d'échec ou d'absence de sauvegarde > 48 h (`alertBackupFailure`, max 1/24 h) ; (10) nettoyage des archives temporaires orphelines au boot + refus d'une destination locale située dans `data/`. **Restauration** : télécharger l'archive B2 → `tar -xzf ls-data-….tar.gz` → recopier le contenu de `data/` extrait dans le volume. ⚠️ lecture des JSON de config robuste au BOM (fichiers créés sous Windows).
- **Déploiement / données prod** : `docker-compose.yml` monte le **volume nommé `ls-data` → `/app/data`** (ajouté le 21/07/2026 — avant ça, chaque push **effaçait** toutes les données de l'espace documents en prod, conteneur reconstruit sans volume). Les données prod survivent désormais aux déploiements ; c'est ce volume que la sauvegarde offsite du déployeur doit archiver (`docker run --rm -v <projet>_ls-data:/data …`).
- **Noms de fichiers générés** : assainis côté serveur via `safeFile()` + `nameDate()` (date `jj-mm-aaaa` sans « / », sinon le navigateur tronquait le nom à « 2026 »).
- **Vue admin globale** : 3 filtres **multi-sélection** (`adminShow` = Dossiers / Comptes / Fichiers, tous actifs par défaut) + barre de recherche `norm()` ; sections empilées (dossiers+leurs docs, comptes, **liste à plat de tous les fichiers** avec `groupLabel`). Dans la **case dossier**, l'**apprenant est affiché avant le formateur** (`membersChips`, `groupTitle`, libellé admin). Notifications : **singulier/pluriel** corrects (« 1 notification non lue » / « 2 notifications non lues »).
- **Pied de page de TOUS les docs générés** (`metaLines` injecté dans `pdfHeaderFooter`/`docxHeaderFooter`) : « Créé le 07/06/2026 par FPE », « Rédigé le {date de génération} par {compte générateur} », « Ce fichier n'a pas encore été modifié — Version 1.0 » (à gauche) + bloc légal `LEGAL_LINES` (à droite).

## Espace documents — génération de documents (Phase 2, FAITE)
- Bouton **« Générer un document »** (formateur/admin, dans un dossier) → modale.
- Modèle **Interactive Worksheet** : en-tête (intitulé, langue, société, noms/tels/mails apprenant+formateur — **préremplis** depuis le dossier) + **notes** (vocabulaire/structure/communication/autre) + **séances répétables** (date/durée, objectifs, liste de mots, structure & grammaire, pronunciation, erreurs à éviter, pour la prochaine fois).
- Brouillon persistant par dossier : `db.worksheets` (1 par dossier, type `interactive`). API `GET|POST /api/worksheet?group=`, `POST /api/worksheet/generate {group, channel}`.
- Flux UI : bouton « Générer » → **modale de choix du modèle** → **modale plein écran** (formulaire) → **un seul bouton « Générer le document »** + choix du **format (PDF ou Word .docx)**.
- Génération serveur : **PDF** via `pdfkit` (`buildWorksheetPdf`), **Word** via `docx` (`buildWorksheetDocx`). Le fichier est **téléchargé directement** sur l'ordi (réponse binaire `attachment`) — **PAS** déposé dans le dossier, pas de choix de canal. Brouillon (header+séances) persistant par dossier (`db.worksheets`).
- Chaque doc généré porte sur **chaque page** : **logo** en en-tête (haut-gauche, `assets/ls-logo.png`) + **pied de page** = numérotation `x / y` + bloc légal à droite (`LEGAL_LINES` dans server.js : Assoc. Loi 1901, siège, RNA, SIRET, QUALIOPI F1017, N° déclaration).
- 1ʳᵉ modale = 2 onglets : **Nouveau document** / **Historique** (`db.docgens`, `GET /api/worksheet/history`). La génération **ne ferme pas** la modale (on vérifie le fichier puis on ferme).
- **Historique GÉNÉRIQUE** : helper serveur **`recordDocgen(g, user, {kind, tpl, title, format, apprenant, snapshot})`** appelé par **TOUS** les générateurs (worksheet, test, attestation, contrat, form, leveltest, presence). ⚠️ **Tout nouveau document à générer DOIT appeler `recordDocgen`** sinon il n'apparaît pas dans l'historique. L'entrée stocke `kind` (icône) + `tpl` (clé picker pour ré-ouvrir). Côté client, l'onglet Historique liste tous les types (icône `HIST_IC` + titre) ; clic = `reopenFromHistory(x)` (worksheet → duplique depuis `snapshot` via `openGenModal` ; autres → ré-ouvre le bon générateur via `x.tpl`, même routage que le picker).
- **Ajout de contact** : bouton 🔍 → **modale de recherche** (prénom/nom/email, **insensible aux accents** via `norm()`), exclut les personnes **déjà** dans un dossier avec soi.
- **Questionnaires (QS) en 2 temps** (`db.qs`, `QS_TEMPLATES` mi-parcours `qs_mid` + fin `qs_end`) : le formateur choisit le modèle → remplit l'en-tête (apprenant/société/langue/intitulé/formateur/date) → **« Envoyer à l'apprenant »** (`POST /api/qs/send`) → message spécial `kind:'qs'` dans le **chat commun** + notif. L'apprenant clique « Remplir » → modale plein écran (questions radio/échelle 1-10/texte) → bouton **« Envoyer votre réponse »** → **popup de confirmation** (`confirmDialog`, 2 boutons : « Confirmer l'envoi » / « Continuer à répondre » ; une fois envoyé il ne peut plus modifier) → `POST /api/qs/:id/submit` (**format PDF forcé**, l'apprenant ne choisit pas) génère le doc (mêmes header/footer) et le **dépose dans le canal commun** (statut « Rempli ✓ » + lien dans le chat). Items typés : `intro|section|radio|scale|text` (+ `comment`). `GET /api/qs/:id` renvoie items+réponses.
- **Tests mi-parcours / fin** (`TEST_TEMPLATES` `test_mid` « Test de mi-parcours de formation » + `test_end` « Test de fin de formation ») : générés **par le formateur/admin** (pas de flux apprenant). Modale plein écran = en-tête (apprenant/société/langue/intitulé/formateur/date, préremplis depuis le dossier) + **Résultat** + **Appréciation formateur** + **zone libre enrichie** + format PDF/Word → `POST /api/testdoc/generate {group,type,header,extra,format}` renvoie le **binaire téléchargé directement** (mêmes header/footer logo+légal, PDF=`buildTestPdf`/Word=`buildTestDocx`). Pas de dépôt dans le dossier, la modale reste ouverte (« Document généré ✓ »).
- **Zone libre enrichie (WYSIWYG)** sous l'appréciation des tests : éditeur `contenteditable` (`richEditorHTML`/`wireRichEditor`) avec gras/italique/souligné/**couleur** (noir par défaut)/listes à puces·numérotées/**tableaux** (modale `tableSizeDialog`, pas de `prompt`)/**QCM** (modale `mcqDialog` : question + réponses, clic = bonne réponse cochée, widget `.rt-qcm` contenteditable=false). Sérialisée côté client en blocs (`serializeRich` walk récursif → `[{type:'p',runs:[{text,bold,italic,underline,color}]}|{type:'ul'|'ol',items}|{type:'table',rows}|{type:'qcm',question,options,answer}]`), rendue **sans titre** sur le doc par `richToDocx`/`richToPdf` (server, QCM = question gras + options `(X)`/`( )`), après l'appréciation.
- **Tous les modèles sont rendus en TABLEAUX/cases** (fidèles aux Word source). Helpers partagés : `dxCell`/`dxTable`/`dxRowMin` (Word) et `pdfCell`/`pdfRows` (PDF, dessin manuel + sauts de page). **Interactive Worksheet** (`buildWorksheetPdf`/`buildWorksheetDocx`) = bandeau titre + tableau en-tête (apprenant/formateur label·valeur sur 2 colonnes + notes vocab/structure/comm/autre) + un tableau par **séance**. **Tests mi/fin** (`buildTestPdf`/`buildTestDocx`) = un tableau (titre + en-tête 2 colonnes + lignes **Résultat** et **Appréciation formateur** encadrées). `ws*`/`testdoc/generate` appellent ces builders.
- **Rendu en TABLEAUX (comme les Word d'origine)** : `buildQsPdf`/`buildQsDocx` regroupent (`qsBlocks`/`sameOpts`) les questions radio consécutives à options identiques en **matrices** (critères en lignes × options en colonnes, case **cochée** = fond accent + ✗/X). Les questions `scale` → tableau **1‑10** (case sélectionnée surlignée), `text` → **encadré** de réponse, `intro`/`section` → paragraphes. PDF = dessin manuel de cellules (rect + bordures, saut de page avec ré-affichage de l'en-tête) ; Word = vrais `Table`/`TableRow`/`TableCell` (shading `ShadingType.CLEAR`, en-tête répété `tableHeader:true`). Concerne qs_mid/qs_end/qs_formateur. (Les tests `test_*` restent en lignes label:valeur via `buildSimpleDoc*`.)
- **Fiche satisfaction formateur** (`FORM_TEMPLATES.qs_formateur` « Fiche satisfaction formateur — bilan de formation ») : questionnaire **rempli PAR le formateur lui-même** (pas l'apprenant), téléchargé directement (à transmettre ensuite à l'admin via le **canal privé**). En-tête propre (Formateur/Langue/Nom apprenant/Intitulé/Date, sans Société) + matrice radio 4 niveaux `SC4F` (Oui tout à fait / Partiellement / Pas vraiment / Non, pas du tout) + question ouverte. `GET /api/form/:type` sert le modèle ; `POST /api/form/generate {group,type,header,answers,format}` (canEditWs) renvoie le **binaire** (réutilise `buildQsPdf`/`buildQsDocx`, désormais génériques via `tpl.headerFields || QS_HEADER_FIELDS`). Modale plein écran (en-tête éditable préremplie + items via `qsItemsHTML`), download direct, modale reste ouverte.
- **Attestation de fin de stage** (`buildAttestationPdf`/`buildAttestationDocx`, `POST /api/attestation/generate`, **formateur + admin**, download direct) : en-tête prérempli depuis les fiches (apprenant/société/intitulé/**dates début→fin**/durée/formateur) + objectifs (1/ligne) + **matrice d'évaluation des acquis** (6 compétences × Acquis / En cours d'acquisition / Non acquis, case ✗) + niveau/certification/résultat + commentaires + signatures. Modale `openAttestationModal`.
- **Contrat de sous-traitance** (`buildContratPdf`/`buildContratDocx` via `contratBlocks(d)`, `POST /api/contrat/generate`, **admin UNIQUEMENT**, download direct) : texte légal complet **version conforme du Word « Contrat sous traitance modèle » (10 articles, verbatim)** — nouvel **article 2 « Périmètre »** (seules les heures **synchrones** sont sous-traitées ; Elearning/certification/gestion restent au Donneur d'ordre, conformité CPF), article 4 enrichi (liste de documents en sous-tirets `li2`, lois influenceurs/fraude CPF, attestations Urssaf), article 5 donneur d'ordre (code conso, L. 6323-9-1), **article 6 financier** (« par heure de cours **synchrone** » + « (soit XXh00 synchrones) ») dont **tous les AJOUTS du nouveau modèle sont rendus EN GRAS** sur le PDF et le Word (blocs `rp` = segments riches `{t,b}` mélangeant normal/gras dans un même paragraphe ; docx = multi-`TextRun`, pdf = `doc.text(...,{continued})` avec bascule Helvetica/Helvetica-Bold), résiliation 9.1/9.2, litiges art. 10 ; **introduction + article 1 préremplis** depuis les fiches (sous-traitant = formateur : naissance/nationalité/adresse/SIRET/NDA ; objet = intitulé/langue/stagiaire/**programme global (pour information)**/**mission confiée (heures synchrones)**/dates/lieu) ; **article 6** = l'admin saisit taux horaire HT/heure synchrone + montant total HT + volume d'heures synchrones. Modale `openContratModal` (entrée picker visible admin seul ; textareas programme+mission préremplies). Représentant L&S = « Antonin HATTABE » fixe (pas de champ). **Référence générée serveur** `newContratRef()` = `Réf. n° {année}/L&S` + **5 chiffres aléatoires uniques** (jamais réutilisés, stockés dans `db.contratRefs`).
- **Level Test** (`LEVEL_TEST` « Évaluation orale / Questionnaire d'objectifs », `buildLevelTestPdf`/`buildLevelTestDocx`, `GET /api/leveltest` + `POST /api/leveltest/generate {group,fields,format}`, **formateur + admin** `canEditWs`, download direct) : fiche d'**intake** remplie par le formateur. En-tête prérempli depuis la fiche (date du jour, langue, nom/prénom apprenant, mail, société, tél) + **champs personnalisés ajoutables** (`fields.extraHeader = [{label,value}]`, bouton « + Ajouter un champ » dans la modale → lignes `.lt-xf`, rendues en fin d'en-tête sur le doc) + objectifs/profil (textareas) + **Besoins** = un **seul tableau 3 colonnes** `Catégorie | Question | Réponse` avec la **catégorie fusionnée verticalement** à gauche (`pdfBesoins` côté PDF, `dxCell` + `VerticalMergeType` côté Word — fidèle au Word d'origine, distinct des évaluations en 2 colonnes) ; sous-catégories Expression orale, Compréhension orale, Expression écrite, Compréhension écrite, Centres d'intérêt (item au label vide → réponse pleine largeur). **Évaluation écrite** et **Évaluation orale** = titre seul + champs éditables **Type de test** (prérempli Cambridge / TOEIC), **Date évaluation**, **Résultat** (barème libre), **Level / Niveau**. Rendu en tableaux (mêmes header/footer logo+légal). Modale `openLevelTestModal` (sous-titres `.lt-cat`).
- **Feuille de présence** (`PRESENCE_TEMPLATES` 3 types, `buildPresencePdf`/`buildPresenceDocx` + `pdfPresenceGrid`, **formateur + admin** `canEditWs`) : modale `openPresenceModal` avec **sélecteur de type** (re-rend le formulaire) → **e-learning** (`kind:'summary'` : en-tête + Nbre d'heures prévues/connexion réalisées + Date du rapport + bloc **Signature Formateur / Signature Apprenant**) · **présentiel-distanciel** et **test** (`kind:'grid'` : en-tête + **grille** créneaux 0:30→10:00 + colonnes Date/Jour/H début/H fin/Durée/**Sign Formateur**/**Sign Apprenant**). Chaque séance répétable `.pr-sess` a un **select « Créneau »** (`s.slot`, options 0:30→10:00, défaut = `nextSlot()` 1ᵉʳ libre) : le serveur place la séance sur **la ligne du créneau choisi** (`slotMap[time]`) et **coche la case** correspondante (PDF = carré rempli accent, Word = ✗ + fond). En-tête prérempli depuis la fiche ; **Lieu** = select Présentiel/Distanciel. (Tous les `<select>` de formulaire sont stylés comme les inputs via `.gf select` / `.pr-sess select` : `appearance:none` + flèche SVG accent.) Titre du doc = « FEUILLES DE PRÉSENCE » (mêmes header/footer logo+légal). Modèles tirés des Word/PDF source ELSYS.
  - **Flux de signatures (comme le QS)** : le formateur **remplit + signe** (pad réutilisable `mountSignaturePad`/`sigPadHTML` : dessin souris/tactile **ou** téléversement d'image → data URL PNG) → **« Envoyer à l'apprenant pour signature »** (`POST /api/presence/send {group,type,fields,formateurSig}`) → message spécial `kind:'presence'` dans le **chat commun** + notif (`db.presences`).
